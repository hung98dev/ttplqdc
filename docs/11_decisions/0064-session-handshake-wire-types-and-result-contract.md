# ADR-0064: Session Handshake, Wire Scalar Types and Result Contract
status: ACCEPTED

## Context
The round-2 network/security review (2026-09-25) found that the handshake and account/character entry path had no wire contract (IDs 1..11 had no fields, no HTTPS endpoint table, no character create/list, undefined resume presentation and pre-session epoch). It also found that UUID, timestamp and `error_code` wire types were undecided; that several results lacked `operation_id`/`status`/`error_code` and many IDs lacked field lists; that protocol error handling conflicted (unknown ID, epoch mismatch, sequence regression, duplicated `client_seq`); that backpressure, L2 rate-limit keys, progressive backoff and auth defaults had no numbers; and that required env vars were missing. The regression review found Steam order handling that could block a season purchase forever or reject a paid order, and an unbounded reward-claim snapshot.

## Decision
- **Handshake**: HTTPS login → `POST /api/v1/gameplay/ticket` → `wss` → `C2S_HELLO` (ticket or resume credential; `session_epoch = 0`, `client_seq = 1`) → `S2C_HELLO_OK` (epoch, rotated resume credential) → `S2C_CHARACTER_LIST` (14) → create (12/13) or attach (6/7). Before `HELLO_OK` any other frame closes with `PROTOCOL_VIOLATION`. The resume credential is single-use, presented only in `C2S_HELLO`. `S2C_PLACEMENT_PENDING` (15) answers attach/respawn/transfer waits under the forced-placement cap. Character deletion stays unsupported.
- **HTTPS endpoint table** for federated login, password register/login, refresh, logout, password change, link/unlink, account read, gameplay ticket, with one `TokenResponse` and HTTP status/error mapping (`../07_security/auth.md` § HTTPS Endpoints). The client-generated `device_id` is a risk signal only.
- **Wire scalar types**: UUID = 16-byte `bytes`; timestamps = int64 Unix ms UTC; positions `sint32` mm; money int64; ratios basis points; `ErrorCode` proto enum (`UNSPECIFIED = 0` = NONE), numbered at the IMP-061 baseline in `errors.md` order and append-only afterwards (`../05_network/protobuf_conventions.md` § 6).
- **Result contract**: every C2S request that can fail gets exactly one typed result with `operation_id`, `status`, `error_code` (new 653 party, 654 friend/block, 655 chat, 710 trade requests, 819 PvP; 649 covers every guild request; 633, 709, 739 fixed); movement/combat intents are answered by 107/204 and dungeon entry by 112. `S2C_FRIEND_STATE` is an `AUTHORITATIVE_EVENT` (full snapshot on attach, then changes); `S2C_BLOCK_STATE` is a full snapshot. Reward claims: 434 sends the 50 oldest plus `total_count`, 439/440 page, 441 delta. Inventory slots carry `locked_quantity`.
- **Envelope validation**: one ordered table in `../05_network/protocol.md`; unknown ID → `MESSAGE_UNKNOWN` without close; epoch mismatch → `SESSION_EPOCH_STALE` and close; sequence regression → `STALE_INPUT` without close; the envelope `client_seq` is canonical (payload copies removed); `correlation_id` = answered request's `client_seq`; more than 20 non-closing rejections in 10 s closes with `PROTOCOL_VIOLATION`.
- **Backpressure**: per-connection outbound queue 256 frames / 1 MiB; replaceable states superseded, deltas merged; slow consumer (> 75% for 5 s or a non-replaceable frame that does not fit) closes with WebSocket 4008.
- **Rate limiting**: L2 key = action + scope (`ACCOUNT` | `USERNAME` | `IP`), two-window sliding approximation (`rate_limit_counters`), progressive login backoff (`auth_failure_backoff`), pinned auth defaults (`../07_security/rate_limits.md`).
- **Steam IAP**: `/steam/init` reuses a pending season order; `QueryTxn` status is the only authority; finalize failure never rejects; `Init` orders expire to `REJECTED` after 24 h; `PENDING -> REFUNDED` covers Google auto-refunds.
- **Env vars**: OIDC audiences, Apple bundle, Play package, RTDN audience/email, admin bind address, TLS mode/cert/key, signal and erasure salts, `BACKUP_STORAGE_URL` / `BACKUP_STORAGE_CREDENTIALS_FILE`, pgBackRest repository variables (`../07_security/external_integrations.md` § 4).
- New error codes: `PROVIDER_ALREADY_LINKED`, `LAST_LOGIN_METHOD`, `CREDENTIAL_CHANGE_LOCKED`, `CHARACTER_NAME_INVALID`, `CHARACTER_NAME_TAKEN`, `CHARACTER_SLOTS_FULL`, `CHAT_TEXT_INVALID`.
