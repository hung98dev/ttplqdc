# ADR-0077: CI Critical Path — Cheap Unity Retries, Fail-Fast Verdicts, Overlapped Image Pull and Two-Phase Verifier
status: ACCEPTED

## Context
Measured Unity-scope PR runs #266–#285 (2026-09-28, after ADR-0075): a clean run takes 4.3–5.3 min; 7 of 14 took 8–10 min, all through retry paths, not missing caches (every Library/editor/EDB/CLI cache hit; 6.2 of 10 GB used).
- Linux materialization, 5/14 runs (#267, #269, #278, #284, #285): attempt 1 on a cache-hit Library self-SIGKILLs (rc=137) ~10 s in at `Begin MonoManager ReloadAssembly` (the BLK-017 signature, now also on the `-quit` path). The loop then slept 60 s and wiped the Library for a 114–160 s cold import: +3.3–4.2 min. On #278 attempts 2–5 each ended `Scripts have compiler errors` (a real compile error of the PR) yet each slept 60 s and cold-imported again (465 s), contrary to ADR-0073 item 5.
- Linux tests, 2/14 runs (#280, #283): EditMode completed 5/5 with `Test run completed. Exiting with code 2 (Failed)`; each identical attempt was retried (~300 s). The Windows job already treats a results XML as final.
- Fixed Linux cost: the image pull (76–101 s) runs after toolchain setup; the kill-probe (apt installs of auditd/bpftrace, tracefs) and five editor version-probe containers add 20–40 s per run, although BLK-008..017 are resolved.
- Each required job runs the whole verifier (35–55 s) only after its Unity job finished, although only Q3 Unity reads Unity results.

## Decision
1. **Warm materialization retry (Linux)**: before the first editor run the job snapshots the cache-restored `client/Library` to `$RUNNER_TEMP/unity-lib-restored` (sudo; never cached). A retry after an editor kill (rc=137) restores that snapshot, removes `client/Temp` and runs at once; attempts 4–5 after kills and every other retry use the clean-Library path (`sudo find client/Library … ! -name PackageCache -exec rm -rf {} +`). The Library a killed editor wrote is never reused (BLK-017).
2. **Materialization back-off**: only a failure that is neither a kill nor a compile error waits 60 s (licence/infra). Compiler errors retry at once on a clean Library (ADR-0073 item 5) and a second consecutive compile-error attempt stops the loop (deterministic). Windows applies the same compile-error rule. Retry bound stays 5; rc=198 still stops at once.
3. **Final test verdicts (Linux)**: a `-runTests` attempt whose real `-logFile` has `Test run completed. Exiting with code` and whose `<Mode>-results.xml` exists but is not the BLK-013 PASS is a final verdict: not retried; the remaining planned modes still run; the step restores the clean Library snapshot and fails; the verifier reports the Q3 FAIL from the uploaded XML. Retries (5, PlayMode 8, BLK-014) remain only for attempts without a completed verdict.
4. **Opt-in kill-probe**: `Arm kill-probe`, `Dump kill-probe diagnostics` and the editor version probes run only while repository variable `UNITY_KILL_PROBE` is `'true'`. They are diagnostics, never gates.
5. **Overlapped image pull**: `Unity (Linux)` starts `docker pull` of the digest-pinned image in the background right after the freeze guard (no secret); the Library cache restores before `Pull Unity image (pinned)`, which joins the pull, falls back to a foreground pull of the same digest on any failure, then tags and inspects the image. No image cache (ADR-0073).
6. **Two-phase verifier**: `cmd/verify -phase pre-unity` runs every gate except Q3 Unity EditMode/PlayMode and writes `$RUNNER_TEMP/verify-pre-unity.json` (schema `verify-pre-unity-v1`, bound to the checked-out HEAD). The required job runs it (`verify.ps1 -Phase pre-unity`, `continue-on-error`) before `Wait for Unity job`; `Run Q0-Q6 verifier` runs `-phase unity -pre-report <file>`, adds the Unity gates in the canonical position and writes `verify-report.json` — same gates, order, commands and verdict as one full run. A missing, foreign-HEAD or invalid file makes the unity phase run every gate. Default (no `-phase`) behaviour is unchanged.

## Consequences
- `.github/workflows/verify.yml`, `scripts/verify.ps1`, `server/cmd/verify` (`-phase`, `-pre-report`; `main_test.go`), `server/internal/conformance/gates/workflow_test.go` (TestUnityImagePullOverlapsSetup, TestKillProbeOptIn, TestMaterializationWarmRetry, TestLinuxTestFailedVerdictIsFinal, TestRequiredJobsRunPreUnityPhase) and `.devin/scripts/cache-policy.md` implement items 1–6.
- `../10_implementation/audit_gates.md` (§ Job Preconditions job layout + item 3) and `../10_implementation/task_queue.md` (`IMP-000` adrs, acceptance, tests) are updated.
- Amends ADR-0073 item 5 (repeated compile errors stop materialization) and ADR-0075 item 1 (the required job runs the Unity-independent gates before joining its Unity job). `cache_warm.yml` is unchanged: its Library jobs run only on an exact-key miss, so there is no restored Library to snapshot.
- Unchanged: retry bounds, licence activation per attempt, network egress, licensing mounts, `-batchmode`/`-nographics`/`setsid`, BLK-013 PASS verdict, drift gate, cache keys, required check names, gate activation.

## Amendment (ADR-0078)
Linux-specific retry items (warm Library snapshot, test watchdog completion verdict, kill-probe opt-in, overlapped image pull) are retired as Unity runs on Windows only. Two-phase verifier runs on `Q0-Q6 verify (Windows)`; compiler-error stop rule applies to the Windows Unity job.
