# ADR-0075: Parallel Unity Jobs, Planned Unity Modes, In-Job Evidence and Pro Concurrency
status: ACCEPTED

## Context
Measured client-touching PR runs (2026-09-28, after ADR-0073): `Q0-Q6 verify (Linux)` ~8 min, `Q0-Q6 verify (Windows)` ~7 min, then a serial `evidence manifest` job (~35 s incl. its own toolchain install). Inside each verify job the Unity steps waited behind the Go/PostgreSQL/protoc setup (~1 min Linux, ~1.5 min Windows), and every PR launched both EditMode and PlayMode although PlayMode's Q3 gate still reports `SKIP(owner-not-done)` (owner `IMP-065`), so a PlayMode flake could fail a job whose verdict did not depend on it. The owner account is on GitHub Pro (user-owned public repository).

## Decision
1. **Parallel Unity jobs**: `verify.yml` runs four jobs per PR — `Unity (Linux)` (`unity-linux`), `Unity (Windows)` (`unity-windows`) and the required `Q0-Q6 verify (Linux)` / `Q0-Q6 verify (Windows)`. A Unity job holds every Unity step (scope, mode plan, editor/image, `client/Library` cache, materialization, tests, drift check, `unity-materialized-windows`, `unity-test-results-<os>`, `visual-review`). The required job does the Go/PostgreSQL/protoc work in parallel, then joins its Unity job with `.devin/scripts/wait_job.sh` (polls this run attempt's jobs API every 10 s), downloads `unity-test-results-<os>`, runs the Q0-Q6 verifier and finally fails unless the Unity job concluded `success` (`Unity job result`). Required check names are unchanged; no job-level `if` is used.
2. **Planned Unity modes**: the Unity job launches only the modes whose Q3 gate is active for the head — owner task (`EditMode` → `IMP-000`, `PlayMode` → `IMP-065`) `DONE` on `main` or in the head, and not a status-only PR — computed by `go -C server run ./cmd/verify -plan-unity` from the same activation predicate and owner constants the verifier gates with (`gates.PlanUnityModes`). Materialization still runs whenever the ADR-0073 scope is `full`. A planned mode without results fails its gate; an unplanned mode reports `SKIP(owner-not-done)`.
3. **In-job evidence**: there is no `evidence manifest` job. After its own verifier, `Q0-Q6 verify (Linux)` waits for `Q0-Q6 verify (Windows)`, downloads `verify-report-windows` (pinned `actions/download-artifact`), merges both reports with `verify.ps1 -MergeReports` into the schema-v2 manifest (ADR-0057/0068 identity rules unchanged) and uploads artifact `evidence`. A missing report yields no manifest; the failing job is already red.
4. **Cache telemetry** of the Unity job rides on `unity-test-results-<os>` (`cache-telemetry.jsonl`) and is folded into the required job's `verify-report.json`.
5. **GitHub Pro**: standard hosted runners allow 40 concurrent jobs (Free: 20). A PR run uses 4 jobs, so the coordinator may keep up to 8 `IN_PROGRESS` tasks (headroom for `cache_warm` and post-merge runs); at most 2 of them may own `client/` paths (Unity licence activations, ADR-0072) unless the licence seat count is raised in Owner Setup. The repository Actions cache limit is raised to 50 GB by the owner. Not used: larger runners and merge queue (unavailable to user-owned repositories), GPU runners (ADR-0058), and a GHCR pre-baked CI image — the Linux Unity job only pulls the digest-pinned GameCI image (~76 s) and installs Go (~8 s); a GHCR image of the same size is still a network pull, so no measurable gain.
6. `wait_job.sh` polling costs ~6 GITHUB_TOKEN requests per minute per waiting job, within the per-repository budget at 8 concurrent tasks.

## Consequences
- `.github/workflows/verify.yml`, `.devin/scripts/wait_job.sh`, `server/cmd/verify` (`-plan-unity`), `server/internal/conformance/gates` (`unityplan.go`, workflow tests) and `server/internal/conformance/caching` (tests) implement items 1–4.
- `../10_implementation/audit_gates.md`, `../10_implementation/agent_execution_protocol.md`, `../10_implementation/README.md`, `../10_implementation/wave_execution_prompts.md`, `../10_implementation/milestones.md`, `../10_implementation/task_queue.md` (`IMP-000`), `../09_testing/test_and_release_evidence.md` and `../00_context/technology_versions.md` are updated; `.devin/agents/coordinator.md`, `.devin/HANDBOOK.md` and `.devin/scripts/cache-policy.md` follow.
- Amends ADR-0058 items 2 and 11 (no third evidence job; concurrency 8 on Pro), ADR-0068 item 6 (evidence merged in the Linux required job) and ADR-0072 item 13 (limit 8 tasks, 2 with `client/`).

## Amendment (ADR-0078)
`Unity (Linux)` job is eliminated; PR verification runs 3 jobs (`Unity (Windows)`, `Q0-Q6 verify (Windows)`, `Q0-Q6 verify (Linux)`). Evidence manifest is merged in `Q0-Q6 verify (Windows)`. Coordinator concurrency limit for client tasks is raised from 2 to 4 tasks (Unity licence activations halved per client PR). Actions cache limit is recorded as 30 GB (owner configuration).
