# ADR-0069: Session Continuity, Auth Hardening and Wire Corrections
status: ACCEPTED

## Context
The round-3 review (2026-09-25) of ADR-0064 found: a superseding ticket login left the live character's state undefined; the resume credential expired 10 minutes after issue and was never re-issued, so most reconnects fell back to the ticket path and the login queue; pending account deletion had no cancel path; any refresh retry revoked the family; a Steam season order could block purchase for 24 h; password backoff let anyone lock out a user and locked shared IPs all day; the login-queue reservation point was undefined; `optional repeated` is illegal proto3; transfer-time input counted toward the protocol reject budget; error numbering scanned prose; `*_RESULT` naming collided with outcome events; rate-limit keys were unsalted; refresh had no absolute cap and Steam/Apple login verification details were missing. The content/client review found the server could not compute the movement-correction trigger because no client message carries a position.

## Decision
- **Superseding login**: a HELLO (ticket or resume) for an account with a live session replaces it and, when a character of the account is live (world or grace), re-attaches that character exactly like a resume (`resumed_character_id`, 7 without 6). `CharacterSummary.is_attached` added.
- **Resume rotation**: new `S2C_RESUME_CREDENTIAL` (16) every 300 s while live; TTL 10 min from issue; at most the newest and its predecessor valid. The ticket path bypasses the login queue while a character of the account is live or in grace.
- **Deletion cancel**: `POST /api/v1/account/delete/cancel` (Bearer, 204, idempotent, `INVALID_STATE` once erasure started, rate limit `account.delete_cancel` 10/h); login never cancels by itself.
- **Refresh**: lost-response grace (N-1 accepted once within 60 s when N was never presented and `device_id` matches); other reuse revokes the family; 30-day sliding TTL with a 90-day absolute family cap.
- **Steam**: re-init queries the pending order; `Approved`/`Succeeded` reused, `Init`/declined/failed → `REJECTED` + new order; `bAuthorized = false` → `/verify` re-query. Login ticket identity `thinhthan-login`; Apple login requires `nonce`.
- **Password backoff**: the password is always verified; a correct password passes a lock; success clears the USERNAME row and the source-IP row; failures decay 1 per 10 min; register limit IP 60/h plus IP+device 5/h; L2 and backoff keys are HMAC-SHA-256 with `ACCOUNT_SIGNAL_SALT`.
- **Login queue**: reservation at ticket issue; attach never returns `SERVER_OVERLOADED`; `retry_after_ms = 5000` for position ≤ 10.
- **Wire**: `EntityDelta` list fields wrapped in `StatusList` / `CosmeticList`; `S2C_STATE_DELTA.self_ack` carries `last_processed_client_seq` and the authoritative self state; the client computes prediction error; `S2C_MOVEMENT_CORRECTION` (107) only for illegal/forced moves with a `reason`. Phase legality table (`../05_network/protocol.md` § Phase Legality); realtime input in DEAD/TRANSFER/PENDING is silently dropped and not counted. `ErrorCode` numbered from fenced blocks only, row-major. 813/818 renamed `S2C_SPARRING_OUTCOME` / `S2C_DUEL_OUTCOME`; detach rejections defined. 202 is the only way to set a target.
