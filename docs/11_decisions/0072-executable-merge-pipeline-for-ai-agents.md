# ADR-0072: Executable Merge Pipeline for AI Agents
status: ACCEPTED

## Context
A round-3 dry run of waves 0–5 on an empty public repository found that the pipeline could not execute as written: agent tokens could not push workflow files or read the freeze variable; parallel PRs deadlocked on "branches must be up to date" with no owner for updating them; Unity project files had to be hand-written without an editor; `IMP-068`'s switch to `pull_request_target` left its own PR without checks; the reviewer had no way to post `policy-review`; blockers were recorded on branches that never merge; local verification could not pass on Linux; the evidence job needed an unpinned action; art tasks had no permitted tool; the merge-guard App could not set the freeze; and the fork guard failed every `push` run.

## Decision
1. **Agent tokens**: one fine-grained token per role session, this repository only: Contents RW, Pull requests RW, Workflows RW, Actions RW, Issues RW, Variables R, Administration R, Secrets R (names), Metadata R.
2. **Merge slot**: GitHub's merge queue is unavailable for user-owned repositories, so the ruleset keeps strict up-to-date branches and the coordinator serializes merges with one `merge-slot` label (lowest topological index first; status PRs first). Only the slot holder merges `origin/main`, re-runs CI, adds evidence, gets a new review and enables auto-merge; implementers stay alive until their PR merges. Three update cycles on one PR open a scoped `OPS-xxx`.
3. **Unity materialization**: every CI job opens `client/` in the pinned editor before any gate, even when every Unity gate is `SKIP`. Files the editor creates or modifies under `client/` are uploaded as `unity-materialized-<linux|windows>` and fail the job with `commit unity-materialized`; the implementer commits them byte-for-byte. Editor-generated GUIDs are accepted; only the ProjectSettings baseline references keep path-derived GUIDs. `.meta` files are owned with their path. No agent machine needs a Unity editor. Licence activation is retried 5 times, 60 s apart, inside the job.
4. **Trusted cutover**: `IMP-000` writes `verify.yml` with `on: pull_request`. The `IMP-068` implementation PR adds `pull_request_target` alongside; its `imp/IMP-068-done` PR removes `pull_request`. No other PR merges between the two.
5. **policy-review**: a check run created by the App through `.devin/scripts/policy_review.ps1` (PowerShell 7, .NET RSA JWT, installation token, create/update check run). The App needs only `checks:write` + `metadata:read`. The script is the only process that reads the key; the exec guard exempts exactly that invocation for `THINHTHAN_AGENT_ROLE=reviewer`.
6. **Blockers on main**: an implementer records a `BLK`/`OPS` entry and sets its task `BLOCKED` in a status-only `block/` PR on the Q0 fast path. The coordinator records merge-guard `ops-blocked` issues and resolves `OPS` entries in `ops/` PRs after the owner closes the issue; the spec-owner resolves `BLK`. OPS entries carry `blocks: <IDs> | ALL`; only `ALL` stops every agent.
7. **Local verification**: `verify.ps1 -LocalDeferMissing` (never in CI) turns a missing Unity editor, PostgreSQL, Windows-only binary or cgo compiler into `DEFERRED(local-missing)`; Linux uses the pinned `postgres:18.6` digest via Docker when available. `verify_delta.sh` tests `./internal/conformance/...`.
8. **Pins**: `actions/download-artifact` v4.3.0, Git LFS 3.8.0 (checkout `lfs: true`), `Google.Protobuf` 3.36.2 NuGet package hash, EDB zip hash. `-race` runs only on the Linux job.
9. **Art tool**: final-art tasks need an owner-provided generation tool recorded in Owner Setup and the version matrix; without it they are not ready and a scoped `OPS-xxx` names them; other work uses the placeholder regime until M10.
10. **Freeze**: the merge-guard App gains Variables and Issues write. While `AUTO_MERGE_FROZEN` is `true`, every job fails its preconditions except on `revert/` and `ops/` branches; the guard clears the variable on the push that merges the resolving `ops/` PR.
11. **Fork guard** runs only on `pull_request` / `pull_request_target`; `push` runs skip it.
12. **Two-phase**: `IMP-083` joins the two-phase list. A `-done` PR runs the task's own gates first and may carry fixes inside the packet's `owned_paths`; a head may set `DONE` before its manifest is committed, and the merged head must contain it.
13. **Concurrency**: at most 2 concurrent tasks with `client/` owned paths (Unity licence activations).

- Amends ADR-0057 (branch roles, freeze and trigger cutover), ADR-0058 (`policy-review` is a check run; merge-guard App permissions; fork guard event scope) and ADR-0068 item 5 (GUIDs are editor-generated except the ProjectSettings baseline references) and item 1 (two-phase list includes `IMP-083`).
