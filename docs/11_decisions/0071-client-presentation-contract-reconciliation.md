# ADR-0071: Client Presentation Contract Reconciliation
status: ACCEPTED

## Context
The round-3 content/client review found contracts an implementer could not apply deterministically: two conflicting Addressables group/key schemes; no group or memory budget for VFX, cosmetics, Linh Thú, icons, props and scenes; no size profile for Linh Thú, props or VFX; a mesh-type rule contradicting the overdraw rule; targeting and portal input without their wire messages; a daily-board family cap contradicting the ADR-0062 fallback; a geometry export that validated camera regions and anchors absent from its schema, float coordinates, and two camera clamp rules; UI PPU and light budgets stated two ways; cutout/volume gate metrics without numeric definitions; three descriptions of Visual Review screenshots; UI state-machine gaps for detach and placement waits; and three Meridian witness strings that are suppressed by FULL_RING.

## Decision
1. **Addressables**: `../04_architecture/client_assets.md` owns the canonical group set (`bootstrap.local`, `shared.local`, `icons.shared`, `beast.shared`, `cosmetic.shared`, `region.<zone_key>`, `dungeon.<dungeon_key>` / `dungeon.finale`, `pvp.shared`, `audio.bgm.<zone_key>` / `audio.bgm.shared`) and the key rule `asset.<catalog_id>.<facet>` / `asset.<kind>.<name>.<facet>` (no variant segment; shared assets through one-hop `PresentationAlias`). `../07_content/presentation_asset_manifest.md` §1 owns per-group download/RAM budgets, deterministic RAM from import settings, resident steady <= 450 MB, transfer peak <= 570 MB and base install <= 82 MB, tied to the 1.3 GB `ANDROID_MIN` cap.
2. **Sizes and import**: new presentation profile `SPIRIT_BEAST` (48x48 silhouette, 64x64 cell, 128x128 texture, no collider); PROP/VFX declare `cell_ref`; mesh type `Tight` when the long side >= 256 texture px with transparent margins, otherwise `Full Rect`; UI imports at PPU 200 (amends ADR-0055); `PARALLAX_FAR` 1x imports at PPU 50.
3. **Gates**: cutout/volume metrics have numeric definitions (edge band, core ring, 8-connectivity flat regions, deterministic 1-D k-means init, per-layer isolated render, one lightness metric ΔL*); declared `.translucent.png` masks exempt only the translucent-marked rules. Visual Review screenshots are rendered by the Linux CI job from `client/Assets/Scenes/Review/`, uploaded as artifact `visual-review`, referenced by evidence manifests and never committed.
4. **Input and UI**: context interact resolves to `C2S_PORTAL_USE` (104) for the nearest portal, else `C2S_INTERACT` (103); targeting uses only `C2S_TARGET_INTENT` (202); `C2S_INPUT_STATE` (100) send-rate rule; `IN_WORLD -> CHARACTER_SELECT` through detach; `TRANSFERRING_MAP.PLACEMENT_PENDING` without client timeout; respawn wait overlay.
5. **Geometry and camera**: `.geom.json` schema v1 with integer-mm coordinates, segment kinds `SOLID_GROUND | SLOPE | WALL | CEILING | ONE_WAY_PLATFORM`, `camera_regions[]` and `anchors[]`; camera regions are owned by the IMP-062 collision scenes (no catalog); one camera clamp rule (active region containing the predicted anchor). Prediction error is computed by the client from `self_ack` (ADR-0069); 107 only for illegal/forced moves.
6. **Light budget** is per quality preset only (`LOW` 4, `MEDIUM` 8, `HIGH` 16; amends ADR-0056).
7. **Content**: board validation allows the single slot-6 fallback 3rd template (ADR-0062); `RELATION_SUBSEQUENCE` is contiguous cyclic; EXPLICIT witnesses become `00111101`, `00100000`, `10101100` (verified by enumerating all 256 sequences).
8. The AOI cap of 40 counts only `entities`; the own character is sent as `self` and is not counted (client hotspot scene = local player + 40 replicated entities).
