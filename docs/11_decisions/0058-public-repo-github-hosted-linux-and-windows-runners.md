# ADR-0058: Public Repository on GitHub-Hosted Linux and Windows Runners
status: ACCEPTED

> **AMENDMENT NOTICE (ADR-0072)**: `policy-review` is an App check run posted by `.devin/scripts/policy_review.ps1` (App permissions `checks:write`, `metadata:read`); the merge-guard App also has Variables and Issues write; the fork guard runs only on `pull_request` / `pull_request_target` events.

## Context
ADR-0050 and ADR-0057 required a self-hosted cloud Windows VM (with a hardware GPU from IMP-095) and allowed the WARP software rasterizer before that. The owner does not want to operate a VM. Owner decision (2026-09-25): the repository is public, CI uses only GitHub-hosted standard runners (free for public repositories), every PR runs a Linux job and a Windows job concurrently, and no GPU runner exists.

## Decision
1. **Runners**: only GitHub-hosted standard runners with explicit image labels: `ubuntu-24.04` and `windows-2022`. Floating labels (`*-latest`), self-hosted runners, GPU/larger runners and owner-managed VMs are forbidden. `windows-2022` is required because the GameCI Windows images are Windows Server 2022 (ltsc2022) containers, which hosted runners run only on a matching host.
2. **Required checks** on every PR: `Q0-Q6 verify (Linux)` (`ubuntu-24.04`) and `Q0-Q6 verify (Windows)` (`windows-2022`), run in parallel, plus the App status `policy-review` (ADR-0057). A third job `evidence manifest` (needs both) merges both verify reports into `manifest.json` and uploads artifact `evidence`; the run concludes `success` only if all three pass. The post-merge guard runs both verify jobs on every push to `main`.
3. **Fork safety (public repo)**: PRs are accepted only from branches of this repository. In every job, the first step fails with `external PRs not accepted` when `github.event.pull_request.head.repo.full_name != github.repository`, before any checkout, cache restore or secret use (a job-level `if` is forbidden because a skipped job satisfies a required check). Secrets are passed only as step `env` after that guard; `pull_request_target` never checks out fork code. The reviewer never posts `policy-review` for a fork PR. Actions setting: require approval for all outside collaborators.
4. **Scripts**: `scripts/verify.ps1` and `scripts/codegen.ps1` are PowerShell 7 (`pwsh` 7.6.6) and run unchanged on Linux and Windows. Canonical command: `pwsh -NoProfile -File scripts/verify.ps1`. Workflow steps use `shell: pwsh`. Bash verify/codegen wrappers stay forbidden (ADR-0050).
5. **Unity**: Unity runs in the digest-pinned GameCI `unityci/editor` images through the SHA-pinned actions `game-ci/unity-test-runner` and `game-ci/unity-builder` (pins in `../00_context/technology_versions.md`). CI runs EditMode/PlayMode with the test-runner action into `<runner temp>/unity-results/` and then calls `verify.ps1 -UnityResultsDir <dir>`, which gates on the result XML (missing or failed results = FAIL); locally `verify.ps1` launches `UNITY_EDITOR_PATH` itself. The licence comes only from repository secrets. `client/Library` is cached per OS with `actions/cache` keyed on `client/Packages/packages-lock.json` and `ProjectVersion.txt`.
6. **Job split**: both jobs run Q0-Q6 (Go tests incl. `-race`, PostgreSQL, codegen drift, Unity EditMode/PlayMode). Linux job only: Unity tests in category `Performance`, Visual Review screenshots, Android IL2CPP build (`ubuntu-6000.6.1f1-android` image). Windows job only: Windows IL2CPP player build (`windows-6000.6.1f1-windows-il2cpp` image). Production server binary is built on the Linux job.
7. **PostgreSQL 18.6**: Linux job = service container `postgres:18.6` pinned by digest; Windows job and local Windows = pinned EDB 18.6-1 binaries zip started by `verify.ps1`. Both export `THINHTHAN_TEST_PG_DSN`. Containers are test-only; production stays container-free (ADR-0052).
8. **Rendering without GPU**: Linux Unity runs under xvfb with Mesa llvmpipe; Visual Review screenshots and draw-call/batch/SetPass/light/particle/memory/load measurements use it and record `renderer=llvmpipe`. Frame timing that depends on GPU speed is never measured on CI. WARP and hardware-GPU requirements are removed.
9. **Client performance**: `PERF-002` becomes a desktop CPU budget measured on the Linux job (`../04_architecture/client_performance.md`). Desktop GPU frame pacing is an accepted, documented gap, mitigated by `PERF-006` budgets and `PERF-003` Android physical-device runs on Firebase Test Lab (unchanged cadence and quota rules, scheduled workflow on `ubuntu-24.04`).
10. **Apps**: `policy-review` comes only from `thinhthan-policy-reviewer`, whose key stays in the reviewer session; post-merge revert PRs use a separate App `thinhthan-merge-guard` (contents and pull requests write, no checks permission) whose key is an Actions secret used only by the guard workflow on `main`.
11. **Limits**: job timeout 120 min (hosted maximum 6 h), Unity step 30 min; a disk-cleanup step before pulling Unity images is allowed on Linux (~14 GB free by default). Coordinator concurrency limit = 5 `IN_PROGRESS` tasks (public repos allow 20 concurrent hosted jobs; each PR uses 2 plus 1 short evidence job).
